# Gersende Ryard de Parcey

**Founder of TruthX / OpenProof · Transformation COO / Interim Executive**

I work at the intersection of operational transformation, governance and crisis reconstruction. My focus is making complex situations understandable: what was expected, what was decided, what the sources support and what remains unresolved.

## What I am building

**OpenProof** helps turn fragmented documents into a structured, source-linked record under human review. **TruthX Engine** is the structuring engine behind the application. The **Registered Probative Object (RPO)** is the record format presented in the public specification.

The first product pilot is **OpenProof Legal**: preparing a reviewable documentary record while preserving contradictions, missing information and explicit reservations. Broader applications in crisis reconstruction and decision traceability remain a development direction, not a claim of released products.

**Status: early prototype retained for context.**

This repository contains an earlier experiment in RPO hashing. Its script and placeholder bundle should not be treated as the current supported verification path or as proof of full RPO conformance.

## Start with the maintained public example

## Product boundary

OpenProof is the application and review workflow. TruthX Engine is its private structuring engine. RPO is the record format. The first product pilot is OpenProof Legal; this repository is not that application.

A hash comparison can detect a change relative to a retained reference. It does not establish source authenticity, factual truth or legal validity. Existing licensing terms in this repository are unchanged.

# OpenProof Validator — project status and verification entry point

**Status: this repository is a scaffold, not a complete validation package.**

The current public verification example is maintained in [openproof-net/rpo-spec-v0.1](https://github.com/openproof-net/rpo-spec-v0.1). Start there rather than relying on the placeholder files here.

## Available checks

The [local demonstration checker](https://github.com/openproof-net/rpo-spec-v0.1/blob/main/tools/verify-demo.cjs) inspects basic fields and compares a SHA-256 fingerprint with a supplied, retained reference. Its tests cover content changes, ordering, malformed structures and the documented command.

[Run the quick start](https://github.com/openproof-net/rpo-spec-v0.1#verify-the-public-example-locally) · [Try browser verification](https://rpo.openproof.net/tests.html)

## Explicit limits

The demonstration does not perform full JSON Schema validation or verify source files, PDFs, signatures or external registry entries. A matching fingerprint does not establish the truth of an assertion or the legal validity of a record. The reference must itself be preserved or authenticated independently where authenticity matters.

The complete OpenProof application and TruthX Engine remain private. The first product pilot is OpenProof Legal.
